# Technical Design: Title

## Purpose

What this subsystem or concern is for, and why a standing design is needed.

## Scope

What this design covers — the components, surfaces, and flows it governs.

## Non-Goals

What this design explicitly does not cover, to keep the boundary sharp.

## Design Principles

The invariants and rules every part of this design must respect.

## Primitives

The minimal set of building blocks this design is allowed to use.

## Boundaries

What each component owns, what it must not own, and where the seams are.

## Runtime Flow

How a unit of work moves through the design from entry to durable outcome.

## Current Versus Target State

Where the implementation is today versus the shape this design defines.

## Acceptance Criteria

The evidence a conforming implementation must produce to satisfy this design.
